# Crypto Research Terminal

本地单用户市场研究与交易管理系统。用行情、结构、资金和事件判断一条机会是否具备条件，把研究计划和预算保存下来，再读后台记录的后续结果。查看行情和研究机会无需登记账户。实际成交与盈亏通过独立的账本接口管理。系统不会向交易所下单。

当前源码版本：**V3.0**（`3.0.0`）。[版本变化与升级说明](CHANGELOG.md)

## 启动与停止

**已有内部便携包**　完整解压后，双击根目录的 `start.bat`。启动器使用包内的 Python 和配置。看到 Uvicorn 开始监听后，打开 [BTC 日线工作区](http://127.0.0.1:8002/crypto?horizon=daily&instrument=btc-usdt-perp)。使用期间保持终端窗口开启，结束时按 `Ctrl+C`。

**从源码运行**　在仓库根目录打开 PowerShell，使用 Python 3.11 或更高版本创建环境。以下命令只在缺少本地配置时复制示例，随后用刚安装依赖的解释器启动服务。

```powershell
cd source
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
if (!(Test-Path .env)) { Copy-Item .env.example .env }
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8002
```

两种方式都监听本机端口 `8002`。源码启动器也可从仓库根目录运行，它优先选择 `source/runtime_python/python.exe`。默认 SQLite 数据库位于 `source/runtime/data/trading_system.db`，本地配置可覆盖数据库和运行目录。

## 首次配置

便携包随包携带配置。源码安装在 `source/.env` 中配置，首次可使用 `.env.example` 的默认值。改完后按 `Ctrl+C` 停止自己的服务，再用原来的方式启动。保留已有配置中的凭据；填写来源时只需处理自己要用的功能。[配置示例](source/.env.example)

| 配置 | 什么时候需要看 |
| --- | --- |
| `WORKER_PROFILE` | 日常桌面使用选 `desktop_light`。仅浏览已有数据时可用 `none`，定时采集与后台追踪随之停止。`desktop_full` 启用更多后台任务。 |
| `PRECOMPUTE_ENABLED` | 示例默认开启。工作区需要后台装配新快照时，检查预计算和对应 worker 是否启用。 |
| `FRED_API_KEY`、`BLS_API_KEY`、`BEA_API_KEY` | 按所需美国宏观序列配置对应来源。各来源的历史覆盖和发布时间可能不同。 |
| `MARKET_EVENTS_TRANSLATE_ENABLED` | 控制新闻翻译。使用示例的腾讯翻译服务时，还需配置对应的凭据。 |
| `APP_RUNTIME_ROOT`、`DATABASE_URL` | 自定义数据位置时核对运行目录和实际连接的数据库。换目录后看到空白历史，先检查当前连接。 |

启动后先打开 [BTC 日线](http://127.0.0.1:8002/crypto?horizon=daily&instrument=btc-usdt-perp)。看到标的、周期、最近一次收盘及其日期，就可以开始读图。如果先看到“准备中”，保持页面打开，等后台任务完成后自动重读。核查服务是否响应可打开[本机存活检查](http://127.0.0.1:8002/api/v1/health/live)，数据是否齐全仍以页面逐项状态为准。

## 一次完整的使用流程

1. **确定看的是哪份行情。** 在 BTC 日线核对标的、产品和周期。读最近收盘与 UTC 时刻，再把鼠标移到图中一根 K 线上，核对其收盘原值。
2. **读出条件。** 在「交易条件与计划」找方向、触发条件、失效边界和目标。若页面说明当前级别不提供结构确认，仍可核对行情和关键位。若显示当前没有已发布机会，本次阅读可以到此结束。
3. **核对证据。** 切到周线看背景、4H 看较短窗口，再回日线。打开「环境与事件」核对观测所属期与事件排期，通过侧栏回到「Crypto 工作区」继续当前选择。需要下次打开相同视图时，收藏带标的和周期参数的地址。
4. **留下计划或跟踪判断。** 有可填写表单时预览并保存计划，需要占用研究预算时再预留。只想观察时，直接点「读取信号记录」。以后回到同一机会，可查看已冻结的判断和新增的跟踪事实。

## 工作区与主图

从 [Crypto 工作区](http://127.0.0.1:8002/crypto) 选择加密标的、产品及周线、日线或 4H。需要研究传统标的时，打开[大宗与美股](http://127.0.0.1:8002/traditional)。当前该页提供 XQQQ-USDT、XAUT-USDT 两种 OKX 现货代币的周线和日线。读 XQQQ 或 XAUT 的价格前先核对页面标出的产品和来源。

| 在主图上操作 | 可以读到什么 |
| --- | --- |
| 鼠标移到某根 K 线，或让图表获得焦点后按左右方向键 | 十字光标对应的时刻、收盘原值和位置。K 线标注的开盘时刻与该周期结束时刻相隔一个周期。 |
| 滚动鼠标滚轮，或按 `+`、`-` | 放大或缩小可见窗口。滚轮以指针附近为中心，便于检查同一局部。 |
| 按住鼠标左键横向拖动 | 在已有历史中前后平移。到达边界说明已经看到该窗口可用的首根或末根。 |
| 按 `Home` 或点图表复位控件 | 恢复默认窗口，继续查看近期走势。 |

**两个日期不同时怎么读。** 主图使用与结构发布配对的 K 线，工作区也会显示独立更新的最新已收盘行情。先看窗口提示，再用与结构同批的 K 线核对图上的关键位。图中时间统一按 UTC 阅读。

**均线看哪一次收盘。** 标为“日线口径”的 SMA50 和 SMA200 使用已收盘日线。当日均线为 100、日收盘为 90、周收盘为 110 时，周线视图中的日线背景仍应读作“日收盘在均线下方”。缺对应日收盘时，只能读取已有均线值。

## 环境与事件

打开[环境与事件](http://127.0.0.1:8002/context)。先看宏观观测的指标名、单位和所属期，再看事件日历的预定时刻、发布状态和来源。新闻提供报道背景；需要核实具体数值时回到对应观测或发布记录。

| 日历显示 | 使用方法 |
| --- | --- |
| 即将公布 | 记录预定时刻，届时回来查看实际发布。 |
| 尚未收到发布值 | 预定时刻已过，本机仍缺实际值；来源是否已经发布需要另行核实。 |
| 有值 · 发布时间待核 | 数值可供当前阅读，最早可知时刻未知。例如归档的 2026 年 10 月 ISM Services 为 52.3，就不能把它当作某个历史决策时刻已经知道的输入。 |
| 已公布 | 结合发布时刻和指标所属期阅读；两者可能相隔数日或数周。 |
| 读取失败 | 点「重新读取」。宏观、日历、新闻各自有状态，可继续阅读成功返回的部分。只有成功读取后的空列表才能说明当前窗口没有收录记录。 |

同比值还需要上年同期基数。若基期缺值，核对页面实际标注的月份；前一期同比只说明前一期。

## 研究计划与预算

在工作区先选定机会，再查看「建立研究计划」。当发布记录缺少必要条件时，这里会列出原因。例如已经给出入场区和止损、却没有可核验的结构目标时，表单会保持关闭。这个状态本身就是本次判断的结果。

1. **填写条件。** 有表单时，核对方向、入场区下沿和上沿、保护止损，按由近到远的顺序填写目标价，多个目标用逗号分隔。计划金额按字段旁的币种填写。
2. **预览。** 展开「费用口径」可填写入场和出场费率、滑点率及每笔最低费用。留空按零成本研究口径计算。点「预览」，核对每单位风险、目标回报及第一目标的回报风险比；字段出现错误时先修正。
3. **保存与读回。** 点「保存计划」，在「已保存计划」核对计划标识、价位和来源。来源为“用户假设”的目标只属于这份推演。要比较另一组参数时，展开「修改条件并另存为新计划」，保留原记录。
4. **管理预算。** 在对应市场和交易级别点「声明研究预算」，填总额并点「声明预算」。保存计划后点「预留预算」，核对预算占用和余额；结束该计划的额度占用时点「释放预留」。声明总额、保存计划、预留额度是三次独立操作。余额不足时本次预留失败，原额度保留。

这些操作产生研究记录和预算流水。真实账户余额和交易所订单另行管理。V3.0 核验的 BTC 归档样本缺少可核验目标，当次未走通真实机会从建立计划到预留预算的完整正向场景。

## 判断记录与复盘

在同一机会下点「读取信号记录」。先读生命周期给出的当前结果，再展开技术明细查看发布时冻结的方向、触发区、目标、止损和分析时点。发布后的进入触发区、触及止损等事件按后续行情记录，因此“发布时已触发”和“后来失效”可以同时成立。

按时间核对跟踪事实，再看是否已有后续闭合 K 线可供重算。显示没有可用 K 线时，结果仍待核验。关掉浏览器后，只要本机服务及相应 worker 继续运行，后台可以继续跟踪；关掉服务会中断后台工作。重新进入页面后再读信号记录，无需手填系统已保留的事实。这里复盘的是判断的演变，账户实得盈亏要用实际成交和资金流水核算。

## 实际账户与账本

现有账户目录、成交、资金事实和已发布报告可通过本机[交互式 API 文档](http://127.0.0.1:8002/docs)操作。以下路径以 `/api/v1/execution` 为前缀。在交互文档中展开相应的 GET 接口，选择 **Try it out**，按字段填写参数并执行，即可查看本机返回的记录。

| 操作 | 入口与核对项 |
| --- | --- |
| 找到账户和成交 | 用 `GET /accounts` 找账户，再用 `GET /fills` 按账户和 UTC 截止时间查成交。单笔详情可用 `GET /fills/{fact_id}` 读回。 |
| 登记真实成交 | 在账本已初始化且具备写权限时，通过 `POST /fills` 提交真实来源、账户和成交身份。金额或数量按接口使用十进制字符串，时间用 UTC。保留请求标识和返回回执，重试同一笔时沿用原身份。 |
| 核对收益报告 | 用 `GET /reports/{report_id}` 读取已发布报告，核对账户、期间、报告币种、估值依据与版本。成本法区分平均成本和 FIFO；资金流、费用原币种及折算口径都会影响解读。 |

当前账本支持基于来源声明的净值预览与期间报告。完整账户资产负债重建、逐笔 PnL 归因和统一管理页面仍有未交付部分。新库或旧库如返回账本未初始化，请依照对应模块的迁移说明核对，停止服务并备份后再应用所需迁移。[账本字段、迁移和报告口径](docs/execution-ledger-api.md)

## 常见问题

| 看到的现象 | 怎样处理 |
| --- | --- |
| 浏览器无法连接 | 确认启动窗口还在运行，地址使用 `127.0.0.1:8002`。若提示端口被占用，先辨认已有进程。需要另一端口时，用源码启动命令显式修改 `--port`，浏览器同步修改地址。 |
| 启动时报缺依赖或缺嵌入式 Python | 便携包重新完整解压。源码安装则回到 `source`，用上文同一个虚拟环境解释器安装依赖并启动。 |
| 页面一直在准备，或行情停留在旧日期 | 先查看任务阶段、上次成功时间和来源提示。检查对应 worker、预计算配置与网络；失败时使用页面提供的重试入口。旧快照仍可用来核对当时的判断。 |
| 只有某个来源或图表为空 | 核对标的、产品、周期、覆盖日期和对应来源的凭据。窗口内真实无结果、来源不支持、请求失败，各有自己的处理方式。 |
| 看得到机会，却不能保存计划或预留额度 | 先读「建立研究计划」列出的缺项，再核对预算是否已在当前市场和级别声明、余额是否足够。 |
| 更换配置后历史记录消失 | 检查实际 `DATABASE_URL` 和 `APP_RUNTIME_ROOT` 是否指向原数据。先找回正确运行目录，再决定是否恢复备份。 |

需要报告问题时，记录页面路径、标的、周期、显示的 UTC 时刻、具体状态和触发操作。默认日志目录为 `source/runtime/logs/`；修改过运行目录时，到相应位置查本次启动的日志。

## 备份与升级

1. **备份。** 停止使用同一数据库的所有服务，等待进程退出。默认部署备份整个 `source/runtime/` 以及本机 `source/.env`。若自定义了 SQLite 路径，一并保存实际数据库目录及其中仍存在的 `-wal`、`-shm` 文件。将副本放在安装目录外，并按凭据文件的权限保管配置。
2. **升级。** 将新便携包解压到独立目录，或更新源码环境。先查[版本记录](CHANGELOG.md)中的升级影响，再核对配置、运行路径及版本。不要用新包里的运行目录覆盖唯一的历史副本。
3. **恢复并核对。** 在服务停止时将备份恢复到独立目录，让配置指向恢复的数据，再启动对应版本。便携启动器固定使用该包的 `source/runtime/`，请在解压副本中恢复到该位置。打开一个已知标的，核对历史收盘、已保存计划或成交记录，再切回日常使用。

私有便携包包含构建时的 `source/.env`。核对交付版本时可查看 git tag 和包清单中的逐文件摘要。构建器默认保留同目录最新的 `CIS-*.zip`，自动删除多余旧包；长期留存的安装包请另行归档。[源码维护与打包](source/README.md) · [工作区 API](source/docs/api/trading-workspace.md)
