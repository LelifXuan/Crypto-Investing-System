# Gold Allocation Page V3 — 精简两段式重构

**日期**: 2026-07-22
**状态**: 设计阶段
**上一版本**: V2 (9 段式布局, 7 模块评分引擎)

## 1. 背景与动机

### 问题

V2 黄金配置页存在结构性缺陷：

1. **数据源硬依赖导致大面积"缺失"** — 7 模块评分引擎假设宏观、GoldHub、XAUT 三条管线都完整，但 GoldHub（WGC 数据）无公开 API，只能手动录入，导致 3/7 模块永久显示"数据不足"
2. **评分逻辑与定投实践脱节** — XAUT 跌 12%、跌破双均线时，引擎因"权重在目标区间内"输出"本月 0 元"，而实际这正是定投加仓的好时机
3. **信息密度高但可操作性低** — 9 段式布局塞满 14 个技术指标、7 个模块卡、硬编码占位图表，用户需要的信息被噪音淹没
4. **DXY 别名映射有 bug** — 数据库存 `dollar_index`，`_gold_macro_snapshot` 查找失败，导致 DXY 信号灯返回 `missing`

### 目标

将页面重构为两段式结构：**上层快速宏观判断 + 下层双栏执行工具**。去掉 GoldHub 依赖，增加 Gate.io 衍生品公开数据，让页面输出的建议真正对齐用户的操作流程。

### 用户操作流程

- **现货**：每月 A 模型（实际利率/DXY/VIX）定性地判断方向 → 基础定投 x 元 → 条件触发时加仓 n×x 元
- **合约**：看 XAUT 技术面 + 衍生品数据，自主判断开平仓

## 3. 上层：宏观环境面板

### 3.1 三个信号灯

| 信号灯 | 数据来源 | 当前 bug |
|--------|----------|----------|
| 实际利率 TIPS 10Y | `indicator_observations` (FRED public CSV) | 无 |
| DXY 美元指数 | `indicator_observations` (FRED public CSV) | 别名 `dollar_index`→`dxy` 映射失效，需修复 |
| VIX 波动率 | `indicator_observations` (FRED public CSV) | 无 |

每个信号灯卡片结构：
- 指标名称 + 代码（TIPS 10Y / DXY / VIX）
- 大字号当前值 + 单位
- 五档 bias 标签：🟢 强势看多 / 🟢 看多 / 🟡 中性 / 🔴 看空 / 🔴 强势看空
- 一句话中文解读（bias_reason）

### 3.2 流动性冲击标签

右上角红色警告，触发条件：`TIPS ≥ 2.0% AND DXY ≥ 105 AND VIX ≥ 25`（三条件同时满足）。

### 3.3 现货方向判断

底部一行综合总结，由三个信号灯 bias 聚合得出。规则：
- 2+ 个信号偏空 → "⚠ 偏谨慎 — 宏观逆风，建议维持基础定投不追高"
- 2+ 个信号偏多 → "✅ 偏积极 — 宏观友好，可考虑适当增加定投"
- 其他 → "➖ 中性 — 宏观不形成方向性约束，按既定纪律执行"

## 4. 下层左栏：现货定投

### 4.1 持仓现状

- 当前权重百分比 + 进度条
- 目标区间（根据宏观评分动态计算：TIPS 低→目标上移，TIPS 高→目标下移）
- 偏离方向标签（低配/达标/超配）

目标区间简化算法（替代 V2 的 7 模块加权，只用 TIPS 和 DXY 两个信号）：

| TIPS 利率 | DXY | 目标区间 | 含义 |
|-----------|-----|----------|------|
| ≤ 0.5% (极低) | 不限 | 10%-15% | 机会成本极低，积极配置 |
| ≤ 1.5% (偏低) | < 105 | 8%-12% | 宏观友好 |
| ≤ 1.5% (偏低) | ≥ 105 | 5%-8% | 利率友好但美元压制，中性偏上 |
| 1.5%-2.0% (中性) | 不限 | 5%-8% | 默认区间 |
| 2.0%-2.8% (偏高) | < 108 | 5%-8% | 利率偏高但美元不强，维持默认 |
| 2.0%-2.8% (偏高) | ≥ 108 | 3%-5% | 双重压制，降低目标 |
| ≥ 2.8% (极高) | 不限 | 0%-3% | 利率极端压制，仅保留跟踪仓位 |

### 4.2 定投公式

x + n × x 可视化：
- x = 基础定投金额（用户可调，默认 ¥500）
- n = 加仓系数（用户可调，默认 ×2）
- 显示触发后合计金额

### 4.3 三层加仓门禁

只有三层全部通过才触发额外加仓 n×x：

**第一层：宏观门禁**
```
TIPS < 2.8% AND DXY < 108
```
若门禁关闭 → 跳过加仓，仅执行基础定投。理由："宏观压制偏强，本月仅执行基础定投"

**第二层：回撤触发**
```
60 日回撤 ≥ 阈值（默认 8%，用户可调）
```
若回撤不够 → 不触发，理由："回撤不足，不触发加仓"

**第三层：指标确认（5 选 3）**

| 指标 | 看多条件 | 看空条件 |
|------|---------|---------|
| RSI(14) | ≤ 40 | ≥ 70 |
| 布林位置 (Price vs BB Lower) | ≤ 0.2 (靠近下轨) | ≥ 0.8 (靠近上轨) |
| 距 EMA20 偏离 | ≤ -2% | ≥ 5% |
| CCI(20) | ≤ -80 | ≥ 200 |
| 成交量异常 | Z ≥ 1.5 (放量下跌确认) | — |

≥3 个指标看多 → 指标确认通过。每个指标显示当前值 + ✓/✗ 标记。

### 4.4 本月建议

最终输出一行：
```
¥ {amount}  {reason}

例：
¥ 500  基础定投（加仓未触发：指标确认 2/5 不满足）
¥ 1,500  基础定投 + 加仓（回撤触发 + 指标确认 4/5）
¥ 0  暂停定投（宏观门禁关闭 + 利率过高）
```

## 5. 下层右栏：合约参考

### 5.1 XAUT 技术面板

全量来自 XAUT 日线 K线（已修复，260 天数据）：

| 指标 | 当前值 | 解读 |
|------|--------|------|
| 最新价 | $4,091.9 | — |
| vs MA50 | $4,350 / 下方 | 中期偏弱 |
| vs MA200 | $4,680 / 下方 | 长期偏弱 |
| 60 日回撤 | -12.0% | 回撤较深 |
| NATR(14) | 1.7% | 波动正常 |
| 成交量 Z | -1.2 | 低迷 |

### 5.2 衍生品数据

| 指标 | 数据来源 | 接入方式 |
|------|----------|----------|
| 永续合约 OI 变化 | Gate.io `GET /futures/usdt/contracts/XAUT_USDT` | 公开 API，无需 Key |
| 永续资金费率 | Gate.io `GET /futures/usdt/contracts/XAUT_USDT` | 公开 API，无需 Key |
| COT 净多分位 | CFTC COT 报告 | 手动输入（月度更新） |

Gate.io 公开端点返回的合约信息中包含 `open_interest` 和 `funding_rate`。OI 变化需要两次快照做差值——服务端维护一个最近 4 周的 OI 缓存：

- 每次刷新时存入 `(timestamp, oi_value)` 到本地 JSON（`runtime/data/xaut_oi_cache.json`）
- 计算 4 周前的 OI 与当前的差值，得到 `futures_oi_change_4w`
- 文件最多保留 5 条快照，自动清理旧于 5 周的记录
- 如果缓存不足 4 周，显示"数据积累中（X/4 周）"

COT 数据留一个手动输入入口（数值 + 日期），存入本地 JSON 文件 `data/goldhub/futures_oi_*.json`（复用现有 GoldHub 管线）。

## 8. 风险与边界

- **DXY 别名 bug** — 在 `gold_macro_adapter.py` 的 `_gold_macro_snapshot` 中修复，同时检查其他别名映射是否正常
- **Gate.io OI 数据** — 公开端点返回的 `open_interest` 是当前快照非历史序列，只能计算 4 周变化需要缓存快照；如果端点不稳定，降级为显示"数据暂不可用"
- **COT 数据** — 月度手动录入，不作为核心依赖
- **向后兼容** — V2 API 端点保留，不影响可能依赖它的其他页面
- **测试** — 新建 V3 前端静态测试 + API 测试；V2 旧测试保留但标记为 deprecated
