## 7. Known follow-ups (low priority)

These are not bugs but improvements the maintainer may want to consider:

1. **`fed_soma_*` refresh policies**: The 6 Fed indicators use FRED series IDs that were just corrected. The `refresh_policies.yaml` entries should be reviewed to make sure the cache TTLs match the FRED update cadence (weekly for `WSHOMCB` / `WSHOTSL`; daily for `IORB` / `RRPONTSYAWARD`).
2. **`TushareMacroProvider` is now `implemented=False`**: Tushare has a working HTTP client (`_api_call`) but no parse logic for `fetch_latest`. The decision to mark it stub was deliberate per Plan D's spec, but a future maintainer with a `TUSHARE_TOKEN` may want to implement the parse logic and flip it back to `implemented=True`.
3. **`tools/audit_user_facing_text.py`**: Restored but not committed anywhere before this session. If the project's CI runs it, ensure CI invokes it. The script exits non-zero on `[FAIL]` patterns and zero on clean text.
4. **`renderDecisionCards` knowledge tooltip UX**: The current implementation wraps the card's `label` text in a `knowledgeTooltip()`. The tooltip text is the term's definition. If the term doesn't exist for a card_id (i.e. `DECISION_CARD_TERM[card.id]` is undefined), the code falls back to `card.id` itself, which would render as raw text. Consider adding a defensive log if a card_id is missing from the map.
5. **`knowledgeCatalogVersion = "v1.10-cleanup"`**: The "cleanup" suffix will need to advance when the next catalog addition lands. Consider adopting a date-based version (`"v1.11-2026-07-XX"`) to keep it self-documenting.
